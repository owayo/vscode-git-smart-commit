# 2026-10-31 定期点検

Git 履歴判定の全件走査をなくし、キャンセル中の拡張停止と複数ルート検出の不具合を修正した。

## 構造と不具合

- 同一実装だった Git の安全な絶対パス解決を `gitExecutable.ts` に集約した。キャッシュは追加せず、呼び出し時の PATH と既存の未検出エラーを維持する。
- 履歴取得失敗時は、コミットの有無を `hasReachableCommit` で判定する。存在・不在・判定不能を区別し、不在と確定したときだけ空配列を返す。実行ファイルの再探索もなくした。
- キャンセル中に error と close が連続すると、後のイベントが shutdown 登録を消していた。登録復元を重複ポーリングの抑止より先に行い、どちらの順序でも拡張停止時の SIGKILL を有効にした。修正前に2ケースの失敗、修正後に4ケースの成功を確認した。
- 削除済み・ファイル化したフォルダーを候補から外し、後続の正常なリポジトリを選べるようにした。権限エラーは伝搬する。リモート拡張ホストの fsPath を扱えるよう、URI scheme は制限しない。

プロセス管理の状態を別クラスへ移す案は見送った。状態を共有する既存の終了処理を分散させる影響に対し、今回の登録復元は局所的な変更で修正できるため。実行ファイル探索のキャッシュも、PATH の変更を毎回反映する仕様を優先して導入していない。

## 性能測定

Darwin / arm64、Git 2.56.0、Python 3.14で測定した。`git fast-import` で空・100件・50,000件の線形履歴を作り、HEAD を未作成ブランチへ向けた。Git のグローバル設定は無効化し、commit-graph は作成していない。同じリポジトリに対して3回ウォームアップ後、旧・新の実行順を交互に変えて各15回測定した。

旧コマンドは `git rev-list --count --all`、新コマンドは `git rev-list --count --max-count=1 --all`。表は中央値で、RSS は子プロセスごとの最大常駐メモリである。

| コミット数 | 時間 旧→新 (ms) | CPU時間 旧→新 (ms) | RSS 旧→新 (KiB) |
| --- | --- | --- | --- |
| 0 | 32.70 → 28.09 | 15.76 → 15.52 | 7,648 → 7,632 |
| 100 | 37.77 → 29.23 | 17.15 → 16.54 | 7,952 → 7,920 |
| 50,000 | 9,085.32 → 75.19 | 342.73 → 16.66 | 21,824 → 8,016 |

50,000件では時間99.17%、CPU時間95.14%、RSS63.27%を削減した。時間の最小–最大は旧2,111.86–12,398.45ms、新25.52–427.63msで、ばらつきを超える改善がある。空・100件は時間の分布が重なるため、高速化とは評価していない。CPU・RSSの中央値に退行はない。通常の履歴取得が成功した場合、この追加判定は実行しない。

[全測定値](history-probe-2026-10-31.json)と再実行用スクリプトを保存した。

```bash
python3 scripts/benchmark-history-probe.py --git "$(command -v git)"
```

## 更新と検証

Vitest / coverage-v8 を5.0.5、vsceを4.0.0、Biomeを2.5.15へ更新した。VS Code API型定義とengineは1.140.0へ揃えた。Node 24.21.0 / pnpm 11.5.2をmiseで固定し、監査で検出した推移依存を修正版へ更新した。

326テスト、型チェック、Lint、VSIX作成が成功し、脆弱性監査は0件。Statements 99.13%、Functions 100%。実Gitによる空履歴・通常履歴・orphan HEAD・無効な候補の結合テストも含む。Marketplace / Open VSX への公開とWindows実機試験は実行していない。

移行情報は[Vitest 5](https://github.com/vitest-dev/vitest/blob/v5.0.3/docs/guide/migration/index.md)、[vsce 4](https://github.com/microsoft/vscode-vsce/releases/tag/v4.0.0)、[minimatch 11](https://github.com/isaacs/minimatch/blob/v11.0.0/changelog.md)を確認した。削除されたminimatch APIをvsceが使っていないことをASTで確認し、パッケージ内容も検証した。

依存更新ツールの初回実行はレジストリ確認がタイムアウトした。環境固定後の再実行は終了コード0、追加更新なしだった。公開後14日未満の `@azure/identity` 4.14.1、`@azure/msal-common` 16.15.0、`@azure/msal-node` 7.1.2、`@isaacs/nonrecursive-glob-match` 1.0.3、`minimatch` 11.0.1 には経過日数の警告が残る。既知の脆弱性を解消する修正版とその推移依存として採用し、この5件が既定の14日条件を満たさないことを記録する。公開からの経過日数フィルターとOSV検証は無効化していない。
